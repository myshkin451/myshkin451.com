# 个人平台重启：创作与设计简报

更新：2026-09-21

本轮目标与顺序已由 [决策 0010](../decisions/0010-creator-first-restart.md) 接受。
具体视觉方向仍待探索。本文件区分用户已经表达的诉求与需要通过样稿验证的判断。

## 已明确的目标

- 网站首先服务自己的创作欲望、持续记录和未来的项目展示。初期没有访问量也有价值。
- 希望有设计、有交互、有自己的想法；现有前台尚未达到这个要求。
- 用户不需要先学习设计术语。代理负责解释选择、提供可感受的方案并归纳反馈。
- 先把网站做得可用、愿意使用，再推进上线；AWS 学习不再是前置条件。
- 域名可以重新选择；Myshkin 451 暂作工作名称。
- 旧平台 skill、旧视觉规范和此前的方案仅作为背景，不约束这次探索。
- 用户进一步明确允许推倒旧工程与设计思路，由代理重新判断实现方式；不再强制沿用旧技术栈。
- 当前没有待发布的文章、照片或项目，可以先把网站与发布流程做起来，之后逐步加入内容。
- 日常写作、发图、发项目、分类与修改应在后台方便完成；新增复杂交互仍可按作品单独开发。
- 用户明确希望访客能注册、登录、留言互动，已纳入[决策 0011](../decisions/0011-zero-content-start-and-visitor-interaction.md)。

## 从空内容开始的使用体验

首个版本同时设计 0 条、1 条和多条内容时的排版。没有内容时保留简洁的身份/介绍与可用的导航；
不要求先发布占位文章，也不把大片“敬请期待”或演示图片当作正式内容。
推荐加入独立留言板，让没有作品时也有交流入口；作品下的讨论可在内容发布后逐项开启。

以下体验已有 [本机前端版本](../../frontend/README.md) 可操作验证；真实账号、跨设备保存与联网发布尚未接入：

| 要做的事 | 期望操作 |
| --- | --- |
| 写文章 | 输入标题与正文，插图，随时存草稿，预览后发布；之后可继续修改或撤下 |
| 发照片 | 选择单张或多张图片，调整顺序，加上可选标题/说明，再发布 |
| 发项目 | 放入名称、链接与可选截图；直接体验的作品不强制填写长篇介绍 |
| 整理网站 | 修改分类、首页精选与顺序，组合已有文字/图片/项目模块，调整基础展示选项 |
| 留言互动 | 访客自由浏览，在要发言时登录；显示昵称，支持回复与管理自己的留言 |

创作端以少填信息为目标，分类、摘要和封面不应无理由地成为保存草稿的障碍。
普通内容使用现成排版；新的整页视觉或新互动仍由开发实现，避免承诺任意无代码编辑。
设计改动尽量保留已发布链接，已发布文章的未完成修改应能留在草稿中。

访客账号与管理账号分开处理；公开展示昵称，邮箱只用于账号用途。留言需要有作者管理入口、
可关闭的讨论与适量防垃圾机制。注册/登录方式先保持简单；具体身份服务与邮件配置在实现时验证。
独立留言板和作品评论保持与正文一致的字体与间距，空状态简单；不需要构建一个完整论坛。

现有离线 HTML 可继续用于审美评审。真正的多人账号、留言和跨设备保存需要应用后端与数据库，
可以先在本机实现、验证，再部署上线。

## 当前设计判断：需要验证的假设

### 9 月 22 日：“版面”方案——把整站排成一份有页边的中文刊物

用户表示此前几轮前端仍与自己想要的个人平台“是两回事”，要求参考优秀设计整体重做。
本轮不再局部调整，而是给 `frontend/` 换了一套统一的视觉系统，假设如下，全部待用户评价：

- **版式而非卡片**：每页都是同一张两栏网格——左侧窄页边（margin）放竖排页眉、日期与类别戳，
  右侧正文栏限宽。首页、内容页、条目页、随记页、关于页共用这张网格，没有独立的“首页模板”。
- **首页是一份按日期倒序的流水账**：一句衬线大字介绍（可在设置中改写）、四类内容入口带计数、
  然后是最近发布的条目流。一条精选领头，其余严格按时间排列；不同形式在同一条流里用不同版式：
  照片保留比例，文章只给标题和一句摘要，项目带预览图与“打开体验”，随记直接展示正文。
- **字体是主要签名**：正文与标题用中文优先的衬线（宋体系），界面文字用系统无衬线，日期、计数、
  戳记用等宽。字标 “Myshkin 451” 用 Iowan Old Style。不引入网络字体，不加图形 logo。
- **颜色只做三件事**：暖纸底、近黑墨字、一点朱红。朱红只用于当前位置标记、精选标记与悬停，
  不用作背景、按钮填充或装饰色块。
- **导航直接指向四类内容**：文章 / 影像 / 项目 / 随记 / 关于 / 留言，取消“内容”总入口，
  全部归档从首页底部与页脚进入。类型筛选改为链接，可直接进入某一类页面。
- **无内容时仍成立**：空状态只剩介绍句与入口，不显示零计数、空卡片与空流。

参考本轮实际截图对照的 Craig Mod、Rauno、Maggie Appleton、The Type、Bartosz Ciechanowski：
分别观察页边与栏宽、极简中的细节密度、个人笔记的组织方式、中文排版的字重与行距、
项目页把互动作品作为正文的做法。未复制任何一家的字体资产、颜色、图形或首页结构。

已验证：格式化、lint、类型检查、75 项单元测试通过；320/390/1440 宽度下十条路由均无横向溢出；
桌面与移动截图覆盖首页、归档、文章、随记、关于（空内容与样例内容）。

这是一次完整替换的设计假设。若用户认可方向，下一步是在真实内容上校准字号、行距与页边比例，
并把 Studio 与账号页面的残余旧样式收进同一套 token；若不认可，应回到本节讨论哪条假设错了，
而不是再做局部修补。

### 9 月 21 日：按访客视角重新整理首页

用户再次指出通用 M 图标、重复巨大姓名与整体模板感，要求审视每个文案、界面、颜色和字体，
并明确首页不必陈列很多内容；即使没有文章、照片或项目也应自然成立。旧个人平台设计技能
不再作为本轮审美依据，不能继续从它推导所谓已经确定的作者气质。

已在 `frontend/` 实现一版入口更简短的首页：小尺寸文字标识、简短问候、三类内容入口与留言链接；
无内容时不显示零计数、搜索工具和空卡片。有内容后只增加最多三项精选或最近发布内容，完整
浏览与筛选放到内容页。预览控件收起在角落，首次访问默认隐藏样例，保留已有浏览器的偏好。
文章不再自动做成重复标题的封面，照片保留比例；关于和账号相关页面减少面向编辑者的说明。

参考沿用本轮实际打开的 Rauno、Craig Mod 和 OpenAI 研究页：分别观察鲜明的构图与浏览方式、
不同媒介的呈现、文字层级与留白。不复制它们的品牌图形、字体资产、口吻和首页结构。
本轮以字体比例、对齐、内容差异和明确入口组织页面，没有新增独立装饰性视觉作品。
这是新的可操作方案，仍待用户评价，不能记录为最终视觉认可。

### 第三轮后的反馈与扩展提案

用户认为第三轮“好了很多”，愿意讨论沿着当前设计继续扩展，表达了“现代极简但是又处处充满设计”
的期望，同时希望适度炫技、开放探索。内容可能包括直接运行的项目、独立网站、文章、自己拍摄的照片、
互动页面及其他尚未确定的创作；文章和其他内容都需要可用的分类方式。
这是对第三轮整体方向的积极反馈，尚未指定 01 或 02 为唯一首页，也不等于接受以下全部提案。

当前建议是以第三轮为基础，让导航、排版与操作保持一致，同时让不同作品采用合适的构图和交互。
审美上的乐趣、惊喜与作者兴趣本身也可以构成交互的理由；无需把每个细节都证明成效率工具。

#### 内容如何组织

从访客可见的体验考虑三个维度，具体名称与数量随实际内容确定：

| 维度 | 用途 | 示例（均为说明，非用户已有内容） |
| --- | --- | --- |
| 内容形式 | 选择适合阅读、看图或体验的入口 | 文章、照片或组图、网站、小工具 |
| 主题 | 在同一种形式内分类，也能跨形式查找 | 阅读、城市、视觉、技术 |
| 专题或系列 | 作者把有关联的内容按顺序组织起来 | 一次出行的文章、组图和路线页面放在一起 |

项目可以包含文章、照片和互动版本。“可互动”描述体验方式，不必强制成为一个与文章互斥的类别。
内容可以有多个主题、加入多个专题；日常发表只需填写标题、内容和必要的入口，分类可以随后补充。
发布后台的正式数据模型留到实际实现时决定，不为这份体验提案提前建立复杂抽象。

每件内容有明确的主要动作：阅读文章、查看组图、开始体验、访问网站。需要时提供次要的“制作记录”
或“源代码”链接。只有一个外部网站入口的作品，也应能直接进入，无需先补写一篇项目介绍。
每次点击去哪里应当从文字和链接提示中看明白，实际交互区域与打开详情的入口分开。

#### 页面与视觉建议

- 首页混排近期内容，并允许少量精选作品采用更大的版面。某一次强调一张照片，不代表永久偏重摄影。
  避免所有条目统一裁成同样大小的封面：照片尊重原始构图，文章可仅有标题与短摘要，项目展示实际界面。
- 把第三轮的并排版与目录版发展成同一批内容的两种浏览方式：先浏览，或直接按标题查找。
  切换时保留搜索、分类和选中项，返回时恢复位置。这是代理建议，尚待样稿评价。
- 文章提供舒适的中文正文、目录、图注与边注，并允许需要时穿插交互演示。
  常规文章可以直接发布；特殊文章再单独设计，控制日常维护负担。
- 摄影支持单张与组图；探索缩略图总览和大图顺序观看。整组作品可以有自己的节奏与颜色。
- 一个独立互动项目可以使用不同的布局、颜色甚至全屏体验，保留明确的返回入口。
  让站点的统一性体现在导航和基础操作上，为作品内部留下创作自由。
- 主题入口默认简洁，需要筛选时再展开。作者编排的专题可以有自己的封面、短介绍和跨形式内容顺序。

优先尝试的细节：照片从缩略位置展开、关闭后回到原位；网格与目录切换时保留内容连续性；
一个作品提供可操作的局部预览；长文中的图解直接响应读者输入。
首页还可以尝试一块更强烈的作品用色或一幅横向长图，检验极简排版能否容纳表达上的变化。
趣味交互可以被发现，但阅读、离开和返回始终直接，触屏与键盘也能完成核心操作。

项目展示界面，影像展示图像本身；交互用于筛选、预览、阅读、看图和取色。
样文与生成图像均明确标识，没有虚构用户已发表作品。

### 第一轮之后的明确反馈

用户认为 B 的视觉效果相对较好，但不满意任何一版的整体结果。主要问题是过多强调、标语和
不自然的文案，包括替作者定义身份、用拟人化句子命名控件、装饰性英文，以及每个区域都要
表达一种态度。不能将“B 更好一些”解释为 B 已获接受。

本轮据此更新设计方法：先查看优秀网站的实际页面，再用生图生成完整效果图，最后按效果图
实现网页。[第二轮预览](studies/restart-02/README.md)记录了参考、效果图、提示词与实现。

- 保留有吸引力的视觉作品；减去与内容无关的口号和反复解释。
- 优先使用具体名称和事实。没有确认的个人介绍就保持简短，不代写“创作者人格”。
- 功能控件直说用途，例如“粗细”“颜色”“自动旋转”，并放在需要操作的位置。
- 首页不承担设计说明、反馈问卷或项目规划；这些留在仓库文档与对话中。
- 旧样稿保留供对照。最终视觉方向继续开放，不把新效果图自动视为用户已接受。

### 仍需验证的判断

用户对 Craig Mod、Rauno Freiberg、Maggie Appleton 三种不同的网站均有好感。
这不足以说明偏好浅色、深色、极简、杂志或数字花园中的某一种。

目前值得验证的是：用户可能更看重清晰的作者性、值得探索的细节，以及内容与呈现之间的
关系。网站需要能容纳写作、技术作品、视觉创作和兴趣变化，不急于把主人固定成某一种职业标签。

现有首页优先展示平台模块、状态和未来规划。重启样稿应尝试让具体作品、文章和人的表达成为
视觉主体。工程状态、CMS 术语和空模块不应承担首页的主要表达。

## 如何帮助用户找出自己的偏好

由代理先提出视觉假设和完整例子，用户通过实际观看、滚动、点击来表达反应。
每轮归纳具体证据，例如标题尺度、留白密度、图片呈现、动效节奏，而不是只记录“高级”或“简洁”。

参考对象各取一个问题，不拼贴整站表面：

| 参考                                           | 本轮观察问题                                       |
| ---------------------------------------------- | -------------------------------------------------- |

## 第一轮交付：三套可操作的视觉研究

[第一轮视觉研究](studies/restart-01/README.md)已实现下列三种假设：A「页间」、B「游乐室」、C「线索」。
它们使用同一组明确标识的示例内容，提供桌面与手机布局、代表性交互、试读以及本地反馈记录。
用户反馈已记录在上方；这些样稿留作对照，不再作为当前推荐入口。

用同一组内容制作三套高保真样稿，每套包含桌面首页、手机布局和一个代表性交互。
它们要在构图、字体、内容组织或交互方式上有明显差异；只改变配色不能算不同方案。

以下是研究方向，不是已选定的品牌隐喻：

| 方向             | 需要验证的体验                                 | 一个可尝试的交互               | 主要风险                                     |
| ---------------- | ---------------------------------------------- | ------------------------------ | -------------------------------------------- |
| 编辑式个人刊物   | 精选内容有主次，文字与作品在同一版面中对话     | 在关联的文字与作品之间切换视角 | 排版精致但过于静态，或把创作变成定期交刊压力 |
| 可探索的创作空间 | 作品拥有自己的形状和展示方式，愿意点开看看     | 一个内嵌、可直接操作的小作品   | 展示效果压过内容，移动端负担太重             |
| 生长中的个人索引 | 已完成作品与最近兴趣自然相连，可以顺着线索浏览 | 展开一条主题与作品之间的关联   | 变成管理面板，或暗示尚不存在的知识系统       |

至少一套应探索更大胆的构图或用色，避免三套都收敛成同一种米白页面。
交互示例可替换；不要求把三个交互全部实现进正式网站。

样稿内容先准备成一个小包：一段个人介绍、一篇文章、一个项目，以及适合公开的一份视觉素材
或演示。优先使用已确认可公开的材料；缺失时用明确标识的样例，不公开私人笔记、客户资料或
本地测试账号。原型内容不自动成为生产数据库内容。

每套交付应带简短说明：它在表达什么、最有辨识度的细节、适合什么内容、牺牲了什么。
选择主要方向后，再补齐文章页与项目详情，检验设计是否能承受真实内容。

## 首个可用版本的边界

- 首页：简短个人表达、精选文字与作品、近期关注；具体组成由样稿决定。
- 写作：可浏览的列表与适合中文长文的详情页。
- 项目：可浏览的列表与能检查作品、说明过程的详情页。
- 关于：足够介绍作者和提供联系入口的小页面。
- 创作流程：通过管理界面写作、发图和发项目；根据便利性决定复用或替换原 CMS。
- 摄影发布：单张、组图、图片顺序与可选说明，支持从后台发布而非改代码。
- 访客互动：注册、登录、留言、回复与基础管理，访客权限与创作管理分离。

摄影与互动内容的具体表面按上方新反馈进入下一版探索；分类与专题先用实际样例验证。
知识路径、独立实验室栏目、订阅、复杂搜索等，在有内容或使用压力时再扩展。
已有占位路由可以保留兼容，但新版导航无需把空栏目作为主要入口。作品内可嵌入小实验，
不必先建设一个完整实验平台。

## 交互与完成标准

基础交互要可靠：链接状态、导航、媒体查看、键盘焦点和触屏操作都应清楚。
在此之上选择少量能表达本站性格的交互，不把效果数量作为设计水平。

- 首页能让人识别作者和具体创作，而不需要先阅读平台说明。
- 用户能指出喜欢的构图与交互，并愿意继续填充内容。
- 文章阅读不被持续动画或过度装饰打断。
- 鼠标、键盘和触屏均可进入同样的核心内容；减少动态效果偏好得到支持。
- 桌面和手机均有真实浏览器检查；不只验证代码成功构建。
- 验证一次文章和项目更新，确保设计没有提高日常发布负担。
- 验证没有内容时的完整页面，再通过后台发布文章、组图与链接项目，检查布局能否自然适应。
- 验证访客注册、登录、留言和回复，以及管理者审核；通过 API 验证访客无法越权。
