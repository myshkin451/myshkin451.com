# 个人平台重启：创作与设计简报

更新：2026-09-16

本轮目标与顺序已由 [决策 0010](../decisions/0010-creator-first-restart.md) 接受。
具体视觉方向仍待探索。本文件区分用户已经表达的诉求与需要通过样稿验证的判断。

## 已明确的目标

- 网站首先服务自己的创作欲望、持续记录和未来的项目展示。初期没有访问量也有价值。
- 希望有设计、有交互、有自己的想法；现有前台尚未达到这个要求。
- 用户不需要先学习设计术语。代理负责解释选择、提供可感受的方案并归纳反馈。
- 先把网站做得可用、愿意使用，再推进上线；AWS 学习不再是前置条件。
- 域名可以重新选择；Myshkin 451 暂作工作名称。
- 旧平台 skill、旧视觉规范和此前的方案仅作为背景，不约束这次探索。

## 当前设计判断：需要验证的假设

用户对 Craig Mod、Rauno Freiberg、Maggie Appleton 三种不同的网站均有好感。
这不足以说明偏好浅色、深色、极简、杂志或数字花园中的某一种。

目前值得验证的是：用户可能更看重清晰的作者性、值得探索的细节，以及内容与呈现之间的
关系。网站需要能容纳写作、技术作品、视觉创作和兴趣变化，不急于把主人固定成某一种职业标签。

现有首页优先展示平台模块、状态和未来规划。重启样稿应尝试让具体作品、文章和人的表达成为
视觉主体。工程状态、CMS 术语和空模块不应承担首页的主要表达。

## 如何帮助用户找出自己的偏好

由代理先提出视觉假设和完整例子，用户通过实际观看、滚动、点击来表达反应。
每轮归纳具体证据，例如标题尺度、留白密度、图片呈现、动效节奏，而不是只记录“高级”或“简洁”。

参考对象各取一个问题，不拼贴整站表面：

| 参考                                           | 本轮观察问题                                       |
| ---------------------------------------------- | -------------------------------------------------- |
| [Craig Mod](https://craigmod.com/)             | 文章、书与图像如何让人感到背后有一个持续创作的人？ |
| [Rauno Freiberg](https://rauno.me/)            | 一个细小的可操作细节，怎样产生探索欲和制作感？     |
| [Maggie Appleton](https://maggieappleton.com/) | 成熟文章、笔记与兴趣如何在同一个空间里共存？       |

偏好在对照之后归纳。代理应给出判断和推荐，同时允许用户否定全部候选。
不要求用户先交出完整设计需求，也不把某个参考站变成模板。

## 下一份交付：三套可操作的视觉研究

用同一组内容制作三套高保真样稿，每套包含桌面首页、手机布局和一个代表性交互。
它们要在构图、字体、内容组织或交互方式上有明显差异；只改变配色不能算不同方案。

以下是研究方向，不是已选定的品牌隐喻：

| 方向             | 需要验证的体验                                 | 一个可尝试的交互               | 主要风险                                     |
| ---------------- | ---------------------------------------------- | ------------------------------ | -------------------------------------------- |
| 编辑式个人刊物   | 精选内容有主次，文字与作品在同一版面中对话     | 在关联的文字与作品之间切换视角 | 排版精致但过于静态，或把创作变成定期交刊压力 |
| 可探索的创作空间 | 作品拥有自己的形状和展示方式，愿意点开看看     | 一个内嵌、可直接操作的小作品   | 展示效果压过内容，移动端负担太重             |
| 生长中的个人索引 | 已完成作品与最近兴趣自然相连，可以顺着线索浏览 | 展开一条主题与作品之间的关联   | 变成管理面板，或暗示尚不存在的知识系统       |

至少一套应探索更大胆的构图或用色，避免三套都收敛成同一种米白页面。
交互示例可替换；不要求把三个交互全部实现进正式网站。

样稿内容先准备成一个小包：一段个人介绍、一篇文章、一个项目，以及适合公开的一份视觉素材
或演示。优先使用已确认可公开的材料；缺失时用明确标识的样例，不公开私人笔记、客户资料或
本地测试账号。原型内容不自动成为生产数据库内容。

每套交付应带简短说明：它在表达什么、最有辨识度的细节、适合什么内容、牺牲了什么。
选择主要方向后，再补齐文章页与项目详情，检验设计是否能承受真实内容。

## 首个可用版本的边界

- 首页：简短个人表达、精选文字与作品、近期关注；具体组成由样稿决定。
- 写作：可浏览的列表与适合中文长文的详情页。
- 项目：可浏览的列表与能检查作品、说明过程的详情页。
- 关于：足够介绍作者和提供联系入口的小页面。
- 创作流程：沿用 CMS 的文章、项目和媒体发布能力；验证日常更新是否方便。

知识路径、独立实验室栏目、评论、订阅、复杂搜索等，在有内容或使用压力时再扩展。
已有占位路由可以保留兼容，但新版导航无需把空栏目作为主要入口。作品内可嵌入小实验，
不必先建设一个完整实验平台。

## 交互与完成标准

基础交互要可靠：链接状态、导航、媒体查看、键盘焦点和触屏操作都应清楚。
在此之上选择少量能表达本站性格的交互，不把效果数量作为设计水平。

- 首页能让人识别作者和具体创作，而不需要先阅读平台说明。
- 用户能指出喜欢的构图与交互，并愿意继续填充内容。
- 文章阅读不被持续动画或过度装饰打断。
- 鼠标、键盘和触屏均可进入同样的核心内容；减少动态效果偏好得到支持。
- 桌面和手机均有真实浏览器检查；不只验证代码成功构建。
- 验证一次文章和项目更新，确保设计没有提高日常发布负担。

## 本轮仓库调整的边界

这次更新确立重启方向、设计方法和后续部署比较，没有实现上述样稿或改写前台。
保留现有技术栈、内容模型、测试与路由；正式视觉实现以样稿反馈为依据。
运行时仍有旧域名默认值和旧前台文案，后续实现及上线前需要明确处理。
