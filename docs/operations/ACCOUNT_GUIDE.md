## 首位站主建立流程（当前已完成邮箱验证和授权）

1. 邮箱服务完成外部收信验证并开放入口后，在网站 `/register` 填写自己的邮箱、昵称和密码。
   密码由本人在安全界面输入，不发送给助手或写入操作记录。
2. 在申请邮件的浏览器打开验证链接，确认网站显示验证完成。收不到邮件时先检查垃圾邮件，
   再使用页面的重新发送验证邮件入口；遵守发送间隔，避免连续提交。
3. 由授权运维核对这个已验证账号的 Auth UUID，再显式授予站主权限。首次注册不会自动成为
   站主，没有默认管理员密码。Vercel 或 Supabase 控制台登录也不等于网站登录。
4. 回到网站登录，进入 `/account` 查看账号状态，再进入 `/studio`。普通访客不能使用工作台。

当前本人账号经真实邀请建立并验证，随后使用网站恢复邮件进入设置密码页。只需完成该页的
密码输入、确认和保存；这些步骤由本人操作。授权范围内的邮件核对可由维护者协助。
不使用测试账号替代本人身份，也不把恢复会话等同于已验证密码登录。

## 日常账号设置

- `/login`：用网站账号登录。公开阅读不需要登录。
- `/account`：查看自己的邮箱、验证与权限状态，修改昵称，管理自己的留言或退出登录。
- `/recover`：未登录时申请找回邮件，在当前浏览器打开邮件后设置新密码；已登录时可修改密码。
- 当前生产邮箱入口已开放；如后续维护关闭，页面会说明不可用，不能据此推断存在默认密码。

昵称修改不追溯修改旧留言的署名快照。密码和验证码始终留在本人界面，不进入聊天、截图证据或日志。

## 站主管理账号

在工作台进入账号管理 `/studio/accounts`，查看邮箱、昵称、邮箱验证状态、角色和限制状态。
只对已经核实属于目标本人的账号操作。

- **授予站主**：目标必须验证邮箱且未受限制。站主可管理所有内容、草稿、留言及账号权限；
  授予前确认对方需要这些完整权限。
- **撤销站主**：目标恢复为普通访客，失去工作台、私有草稿和私有媒体的新访问权限。
- **限制账号**：禁止该账号在本站写入和使用站主权限；这不是禁止 Supabase 登录。
  受限者仍可阅读公开内容、查看本人账号和留言。若目标原为站主，操作同时撤销站主角色。
- **恢复账号**：解除本站限制。不要假定恢复会自动重新授予站主；以页面显示和明确操作为准。
  如果认证服务本身封禁了账号，需要授权运维先在认证控制台恢复。

操作后检查成功提示及刷新后的角色/状态。失败时按错误提示处理，不把按钮点击当作成功。
系统拒绝自己撤权或限制自己，并保护最后一位有效站主。供应商管理员直接删除账号或改表不受
这些页面保护约束，不能用控制台随意绕开它们。

限制和撤权会作用于已有登录会话的后续 API 请求。已经下载的文件无法收回，先前签发的图片
链接也可能持续到到期；因此不要把撤权描述为立即销毁对方已有资料。
